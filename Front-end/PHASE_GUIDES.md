## 🔍 Phase 1: Discovery 🔍

**Duration:** 2-3 days  
**Lead Agent:** Briefing  
**Supporting Agents:** SEO, UX/UI  
**Milestone:** Complete project brief signed by client

### Day 1: Initial Client Meeting

#### Morning (9:00 - 12:00)

**1. Preparation (Before meeting)**
- [ ] Review any existing client materials
- [ ] Prepare intake questionnaire (from TEMPLATES_BRIEFING.md)
- [ ] Schedule 60-min discovery call
- [ ] Prepare video recording setup (get permission)

**2. Discovery Call (60 min)**

Follow this structure:
```
1. Introduction & Rapport (5 min)
   - Welcome, intro team
   - Set expectations for call
   - Explain next steps

2. Business Context (10 min)
   - What's your company/product?
   - What problem do you solve?
   - Who are your customers?
   - What's your market position?

3. Project Goals (10 min)
   - Why are you doing this project now?
   - What success looks like?
   - What's your timeline?
   - What's your budget?

4. Target Audience (10 min)
   - Who's your primary user?
   - What are their pain points?
   - How do they find you currently?
   - What would make them choose you?

5. Current Situation (10 min)
   - Do you have a site currently?
   - What's working/not working?
   - What's the competition doing?
   - Unique advantage?

6. Requirements (10 min)
   - What features do you need?
   - Any technical constraints?
   - Integration requirements?
   - Data/content availability?

7. Metrics & Success (5 min)
   - How will we measure success?
   - Timeline expectations?
   - Next steps explanation?
```

**3. Documenting During Call**
- [ ] Record all answers (with permission)
- [ ] Take notes on key points
- [ ] Mark unclear areas for follow-up
- [ ] Capture specific examples/stories
- [ ] Get contact info for follow-ups

#### Afternoon (14:00 - 17:00)

**4. Initial Analysis**
- [ ] Transcribe recording (or summarize notes)
- [ ] Create initial project profile
- [ ] Identify information gaps
- [ ] List follow-up questions
- [ ] Share with team for input

**5. Follow-up Communications**
- [ ] Send thank you email with next steps
- [ ] Ask for any supporting documents
- [ ] Request access to existing materials
- [ ] Schedule follow-up for Day 2

  - Long-tail keywords

**3. Follow-up with Client**
- [ ] Ask clarifying questions from Day 1
- [ ] Review competitive analysis with client
- [ ] Refine scope and priorities
- [ ] Confirm timeline and budget
- [ ] Get stakeholder buy-in

**4. Internal Alignment**
- [ ] Share findings with team

## 📊 Phase 2: Planning 📊

**Duration:** 2-3 days  
**Lead Agents:** Front-end, SEO (joint)  
**Supporting Agents:** Briefing, UX/UI, QA  
**Milestone:** All team members aligned on approach

### Day 4: Architecture & Stack Decision

#### Morning (9:00 - 12:00)

**1. Tech Stack Decision Meeting**

Team assembled: Front-end (lead), SEO, UX/UI, QA, Briefing

**Agenda (90 min):**

1. **Presentation** (20 min)
   - Front-end presents 2-3 stack options
   - Each option with pros/cons
   - Recommendation with rationale
   - Trade-off analysis

2. **Discussion** (40 min)
   - SEO: Does it support SEO needs?
   - UX/UI: Does it enable the design vision?
   - QA: Is it testable?
   - Briefing: Does it meet business goals?

3. **Decision** (30 min)
   - Consensus on primary stack
   - Fallback options documented
   - Rationale documented
   - Sign off

**Example Stacks:**
- **SaaS Dashboard:** Next.js + React + TypeScript + Tailwind + Zustand
- **Marketing Site:** Next.js (SSG) + Tailwind + Vercel
- **E-commerce:** Next.js + React + TypeScript + PostgreSQL + Stripe
- **Content Platform:** Next.js + Tailwind + MDX (for blog)

**Decision Document:**
- [ ] Primary stack selected
- [ ] Technology rationale (why each choice)
- [ ] Trade-offs documented (why NOT alternatives)
- [ ] Performance implications
- [ ] Team expertise alignment
- [ ] Team sign-off

#### Afternoon (14:00 - 17:00)

**2. System Architecture Design**

Front-end lead creates architecture diagram:
- [ ] Frontend architecture
  - Pages/routes structure
  - Component hierarchy
  - State management approach
  - API integration pattern
- [ ] Data flow
  - How data enters system
  - How it's processed
  - How it's displayed
  - Caching strategy
- [ ] Backend (if applicable)
  - API endpoints needed
  - Database schema
  - Authentication/authorization
  - Deployment target
- [ ] External integrations
  - Analytics
  - Payment processing
  - Email service
  - CMS (if applicable)

**Document:**
- [ ] System architecture diagram
- [ ] Data flow diagrams
- [ ] API contract (endpoint list)
- [ ] Tech decisions rationale
- [ ] Team Q&A session

- [ ] Content calendar (spreadsheet)
  - Topics/keywords
  - Month scheduled

**3. Design System & Component Inventory**

UX/UI lead with Front-end input:

### Development Standards

**Code Organization**
```
src/
├── app/                    # Next.js app router
├── components/
│   ├── ui/                # Design system components
│   ├── layout/            # Layout components
│   ├── sections/          # Page sections
│   └── features/          # Feature-specific
├── lib/                   # Utilities
├── styles/                # Global styles
├── hooks/                 # Custom hooks
├── types/                 # TypeScript types
└── utils/                 # Utility functions
```

**Naming Conventions**
- Components: PascalCase (Button, UserProfile)
- Functions: camelCase (formatDate, handleClick)
- Constants: UPPER_SNAKE_CASE (MAX_ATTEMPTS)
- Files: Match component name (Button.tsx, useAuth.ts)

**Testing Requirements**
```typescript
// Every component should have tests
describe('Button', () => {
  it('renders correctly', () => { });
  it('handles click', () => { });
  it('applies variant styles', () => { });
  it('is accessible', () => { });
});
```

**TypeScript Standards**
```typescript
// No `any` types
// All props interface
interface ButtonProps {
  variant: 'primary' | 'secondary';
  size: 'sm' | 'md' | 'lg';
  onClick: () => void;
}

// Export types
export type { ButtonProps };
```

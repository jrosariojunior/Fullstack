### Day 4: Operating Rules Deep Dive (2 hours)

**The 8 Operating Rules of the Framework**

**Rule 1: Discovery is Mandatory, No Shortcuts**
- Briefing must complete full discovery before proceeding
- Time: 3 days minimum
- Why: Ambiguity early = problems later
- Failure Mode: Skipping discovery leads to scope creep

**Exercise:** 
- Briefing agent presents discovery findings
- Team asks questions to validate completeness
- Identify gaps in requirements

**Rule 2: Briefing Sign-Off Before Tech Decisions**
- Front-end cannot make tech stack decisions until briefing is complete
- Why: Tech should serve requirements, not the other way around
- Failure Mode: Wrong technology for the problem

**Rule 3: SEO is Part of Planning, Not an Afterthought**
- SEO agent shapes information architecture in Phase 2
- Site structure must support keyword strategy
- Why: Changing structure late is expensive
- Failure Mode: Ranking #50 for target keywords after launch

**Rule 4: Design System Before Individual Components**
- UX/UI creates system-wide decisions before designing pages
- Decisions on: Colors, typography, spacing, components
- Why: Consistency, reusability, faster design-to-code
- Failure Mode: Design inconsistency, component reimplementation

**Rule 5: Performance is Not a Phase, It's a Discipline**
- Every phase measures and optimizes performance
- Discovery: Understand performance requirements
- Planning: Architect for performance
- Design: Design for fast interactions
- Development: Implement with performance in mind
- Audit: Measure against targets
- Why: Adding performance at the end is 10x harder
- Failure Mode: Lighthouse 45, Core Web Vitals red

**Rule 6: Accessibility is Baked In, Not Added On**
- Every design decision must consider accessibility
- Every component must pass WCAG 2.1 AA
- This is non-negotiable
- Why: Accessibility = good UX for everyone
- Failure Mode: 20% of users can't use your site

**Rule 7: No Handoff Without Documentation**
- Phase boundaries require formal handoff documents
- Document format: From AGENT_GUIDELINES.md → Handoff Templates
- Why: Prevents misunderstandings, enables async work
- Failure Mode: "Wait, I thought we decided..."

**Rule 8: Continuous Improvement, Every Project**
- After Phase 5, capture what worked and what didn't
- Update framework based on learnings
- Why: Framework gets better with each project
- Failure Mode: Repeating same mistakes

**Discussion Exercise:**
- Which rules are hardest to follow?
- When would you want to break them? (and why you shouldn't)
- How do rules prevent common project failures?

**Day 2: Implementation & Performance (4 hours)**

**Session D1: Performance Optimization**

Core Web Vitals Targets:
- LCP (Largest Contentful Paint): < 2.5s
- FID/INP (Interaction to Next Paint): < 100ms
- CLS (Cumulative Layout Shift): < 0.1

How to achieve these:
1. **Image Optimization:**
   - Use next/image component
   - Serve WebP format
   - Lazy load below fold
   
2. **JavaScript Optimization:**
   - Code splitting (automatic in Next.js)
   - Tree shaking for unused code
   - Dynamic imports for large components

3. **Caching Strategy:**
   - Static generation (ISR) when possible
   - Revalidation timing
   - Cache headers for browser/CDN

4. **Database Queries:**
   - N+1 query prevention
   - Proper indexing
   - Query result caching

**Lighthouse Audit Exercise:**
- Review a slow website (provided example)
- Identify performance bottlenecks
- Create optimization plan
- Estimate impact of each optimization
- Compare estimated vs. actual improvement

- **E2E Tests:** Critical user journeys
- **Visual Tests:** Design consistency

**Session C2: Site Structure & Architecture**

SEO-Optimal Information Architecture:

Example: E-commerce Site
```
/                       (Homepage)
/shop                   (Category listing)
/shop/[category]        (Category page)
/shop/[category]/[slug] (Product page)
/blog                   (Blog listing)
/blog/[slug]            (Blog post)
/about                  (About page)
```

Why this structure?
- Clear hierarchy for crawlers
- Keyword opportunities at each level
- Natural internal linking
- Breadcrumb trail for users

**Anti-patterns to Avoid:**
- ❌ /product.php?id=123 (parameter-based, not crawlable)
- ❌ /p/xyz (URLs don't tell you about content)
- ❌ Infinite pagination (crawlers can't reach page 50)
- ❌ Behind login/JavaScript (only after page loads)

**URL Optimization:**
- Use keywords in URL: /seo-best-practices (not /guide/12345)
- Keep short and descriptive: /seo (not /things-to-do-about-seo)
- Use hyphens not underscores: seo-tips (not seo_tips)
- Avoid stopwords when possible

**Exercise: Design Site Structure**

- Plan internal linking strategy

**Day 2: Technical SEO & On-Page Optimization (4 hours)**

**Session D1: Technical SEO Implementation**

Critical Technical Elements:

1. **Core Web Vitals**
   - LCP < 2.5s (images, fonts, blocking resources)
   - INP < 200ms (interactivity)
   - CLS < 0.1 (layout shifts)
   - Front-end agent owns this, SEO monitors

2. **XML Sitemap**
   - Auto-generated by Next.js
   - Include all important pages
   - Update when content changes

3. **Robots.txt**
   - Allow crawlers to all important pages
   - Block /admin, /api, /private pages
   - Set crawl delay if needed

4. **Meta Tags**
   - Title (50-60 chars, keyword first if possible)
   - Description (120-160 chars, compelling)
   - Canonical URL (prevent duplicates)
   - Open Graph tags (social sharing)

5. **Structured Data**
   - Schema.org markup (JSON-LD)
   - Product schema for e-commerce
   - Organization schema on homepage
   - Helps Google understand content

6. **Redirects**
   - 301 redirects for old URLs
   - Passes link equity to new URL
   - Update when migrating content

**Session D2: On-Page Optimization**

Content Optimization:

1. **Title Tag**
   - Primary keyword at start
   - Compelling (people want to click)
   - Accurate (set expectations)
   - Example: "SEO Best Practices Guide 2026 | 50+ Tips"

2. **Meta Description**
   - Answer the question implied by keyword
   - Call-to-action when appropriate
   - Accurate (no misleading claims)
   - Example: "Learn proven SEO strategies that increased ranking 10x. 50+ actionable tips from industry experts. [Read Guide]"

3. **Heading Hierarchy**
   - H1: Page topic (usually matches title)
   - H2: Main sections
   - H3: Subsections
   - Only one H1 per page

4. **Content Optimization**
   - Keyword in first 100 words
   - Natural integration (not keyword stuffing)
   - 2000+ words for competitive keywords
   - Address user intent (what are they actually looking for?)

5. **Internal Linking**
   - Link to related content
   - Use keyword-relevant anchor text
   - 3-5 internal links per page
   - Link to high-authority pages

- Rewrite for SEO
- Compare with expert optimization

### Option D: UX/UI Agent Deep Dive (2 days)

**Day 1: Design System & Component Library (4 hours)**

**Session D1: Building a Design System**

What is a Design System?
- Single source of truth for design decisions
- Speeds up design-to-code process
- Ensures consistency across app
- Makes design handoff to developers easier

Components of a Design System:

1. **Color Palette**
   - Primary, secondary, accent colors
   - Neutral grays (for text, backgrounds)
   - Semantic colors (success, warning, error)
   - Accessibility: 4.5:1 contrast for text

2. **Typography**
   - Font families (usually 1-2)
   - Font sizes (8 scale steps)
   - Font weights (regular, medium, semibold, bold)
   - Line heights (1.2 for headings, 1.5 for body)

3. **Spacing Scale**
   - Increments: 0, 2, 4, 8, 12, 16, 24, 32, 48, 64px
   - Used for padding, margins, gaps
   - Consistency creates visual harmony

4. **Components**
   - Button (primary, secondary, tertiary, disabled)
   - Input (text, email, password, search)
   - Card (with/without actions)
   - Modal (sizes, positions)
   - Nav (horizontal, vertical)
   - Etc. (20-50 components total)

5. **Design Tokens**
   - CSS variables that reference design system
   - Example: --color-primary, --spacing-md
   - Makes theming/white-labeling possible

**Exercise: Create a Design System**
- Given brand guidelines
- Create color palette (8 colors)
- Select typography (2 fonts, 6 sizes)
- Define spacing scale
- Specify 10 core components
- Create component specs (variants, states)

**Session D2: Accessibility & Usability**

WCAG 2.1 AA Compliance (What You Must Do):

1. **Perceivable**
   - Color is not sole way to convey information
   - Sufficient contrast (4.5:1 for normal text)
   - Alternative text for images
   - Captions for videos

2. **Operable**
   - Keyboard navigation (Tab, Enter, Escape)
   - No keyboard traps (you can tab out)
   - Focus indicators visible
   - No flashing content

3. **Understandable**
   - Clear language (no jargon)
   - Consistent navigation
   - Predictable interactions
   - Error messages that help fix problems

4. **Robust**
   - Valid HTML and CSS
   - Proper semantic markup
   - ARIA labels when needed
   - Compatible with assistive technology

**Accessibility Checklist for Designers:**
- [ ] All text has 4.5:1 contrast with background
- [ ] Color is not sole way to convey meaning
- [ ] Focus state is clearly visible on interactive elements
- [ ] Buttons have text labels (not just icons)
- [ ] Forms have associated labels
- [ ] Images have descriptive alt text
- [ ] Videos have captions

**Day 2: High-Fidelity Mockups & Developer Handoff (4 hours)**

**Session E1: Designing for Development**

Design-to-Code Best Practices:

1. **Use a Design System**
   - Every component is in the design system
   - Developers use code components that match
   - Consistency is automatic

2. **Specify Everything**
   - Font size, weight, line height
   - Color (hex code)
   - Spacing (exact pixels)
   - Border radius, shadows
   - Hover/active/disabled states

3. **Component Specifications**
   - Show all variants
   - Document interactions
   - Include error states
   - Show loading states

4. **Responsive Design**
   - Mobile (375px breakpoint)
   - Tablet (768px breakpoint)
   - Desktop (1024px+ breakpoint)
   - Specify how layout changes

5. **Developer Handoff**
   - Clear file organization in Figma
   - Component descriptions
   - Design token names match code variable names
   - Use Figma Dev Mode or export for developers

**Session E2: Responsive & Interactive Design**

Mobile-First Approach:
- Design mobile first (most constrained)
- Then tablet
- Then desktop
- Ensures essential content on mobile

Common Responsive Patterns:
1. **Stack:** Columns become rows on mobile
2. **Hide:** Less important elements hidden on mobile
3. **Reflow:** Navigation collapses to hamburger
4. **Resize:** Font sizes reduce on mobile

Interactive Elements:
- Buttons (should be 44x44px minimum on mobile)
- Links (should be tap-friendly)
- Modals (should be full-screen on mobile)
- Dropdowns (should become bottom sheets on mobile)

Testing Pyramid:
```
        E2E Tests
      Integration Tests
    Unit Tests
```

**Unit Tests (70% of tests)**
- Test individual functions/components in isolation
- Fast to run (milliseconds)

**E2E Tests (10% of tests)**

- Slow to run (seconds/minutes)
- Test complete workflows
